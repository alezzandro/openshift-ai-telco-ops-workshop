= How to use the playground

This site is the **student playground**. Work in the Data Science Project the facilitator assigned (`{ran_project}` or `{core_project}`).

The blue banner at the top is filled from this cluster. Use those links; do not copy hostnames from an older lab.

== What you will do

. Read xref:playground-rules.adoc[Rules].
. Register a model version in Model Registry **workshop**, then deploy that version from **AI hub → Registry** (not the catalog **Deploy** button).
. Call your model from a laptop with the **external Route** and a `workshop-infer` token (curl or Python). Do not use Open WebUI Direct Connections.
. Work through xref:p1-p8-exercises.adoc[exercises P1–P8], then xref:p9-gen-ai-playground.adoc[P9] (**Gen AI studio → Playground** plus OpenShift MCP — Technology Preview).

== What you will operate

* {rhoai_product} {rhoai_version} dashboard
* Model Registry **workshop**
* Your model's authenticated OpenShift Route (curl / Python)
* OpenShift AI **Observe & monitor → Infrastructure** (GPUs and Kueue queues) and **Dashboard → Models** (Deployed models)

You will *not* load GGUF files into Open WebUI. You will *not* edit operators or MachineSets.

Your HTPasswd user is **cluster-admin** so you can inspect Kueue queues, nodes, and Observe. That is a classroom shortcut, not production tenancy. Kueue already admits every GPU deploy you make from the dashboard (Hardware profile → LocalQueue `workshop` → ClusterQueue `gpu-pool-2l4`, **6 GPU** on class day). Your project cap is OpenShift `ResourceQuota` **5 GPU** — high enough to oversubscribe the pool so P5 can show a queue, not only Forbidden. xref:p1-p8-exercises.adoc#p5-kueue[P5] and xref:p1-p8-exercises.adoc#p6-isolation[P6] say what is demo-only and how real isolation is built.

== Official names

Use **Red Hat OpenShift** and **Red Hat OpenShift AI**. This lab is serving operations, not RAN CNFs and not model training.
