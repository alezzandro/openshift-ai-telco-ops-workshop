= C4b. Package a Hugging Face model as a ModelCar

Time: about 8 minutes. Skip on a 60-minute cut.

Same governed path as C3 and C4: **register a version in Model Registry workshop**, then **deploy that version**. This time the artifact is an **OCI ModelCar** you built, not a catalog card and not an S3 prefix.

https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_on_projects/using-connections_projects[Use connections]

https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_with_model_registries/working-with-model-registries_model-registry#registering-a-model-from-the-dashboard[Register a model from the dashboard]

== Story

Catalog ModelCars are the supported path when Red Hat already publishes the image. A data-science team still shows up with an arbitrary Hugging Face snapshot. Two production-shaped options:

. Land weights in **enterprise object storage** and deploy from S3 (C4).
. Wrap the snapshot as a **ModelCar** (UBI9 image, files under `/models`) and pull it like any other OCI artifact.

Dashboard **Register and store** can bake a ModelCar for you. This lab shows the Containerfile so you can talk about reproducibility, air-gap, and the in-cluster registry.

== 1. Show the Containerfile

Official pattern: a UBI9 base **with a shell**, model files under `/models`, world-readable, non-root user. KServe uses the shell to make those files visible to vLLM. Do not use `scratch`.

https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/deploying_models/deploying-models_rhoai-user#storing-a-model-in-an-oci-image[Store a model in an OCI image]

From the repo (`manifests/modelcar/Containerfile`):

----
FROM registry.access.redhat.com/ubi9/python-311:1 AS fetch
USER 0
RUN pip install --no-cache-dir "huggingface_hub>=0.24,<3"
ARG HF_REPO_ID=ibm-granite/granite-3.3-2b-instruct
ENV HF_HUB_ENABLE_HF_TRANSFER=0 HF_REPO_ID=${HF_REPO_ID}
RUN python3 -c "from huggingface_hub import snapshot_download; import os; snapshot_download(repo_id=os.environ['HF_REPO_ID'], local_dir='/opt/app-root/src/models')"

FROM registry.access.redhat.com/ubi9/ubi-minimal:9.6
COPY --from=fetch --chown=0:0 /opt/app-root/src/models /models
RUN chmod -R a=rX /models
USER 65534
----

Talking point: "First stage pulls Hugging Face. Runtime is UBI9 Minimal. Same image the cluster already built into the in-cluster registry."

Optional: OpenShift console → project `{presenter_project}` → Builds → `modelcar-granite-3-3-2b-instruct` → complete ImageStreamTag `workshop`.

== 2. Connection (pull secret)

The internal registry is **not** in the cluster global pull secret. Catalog connection **Red Hat catalog ModelCars** (`registry.redhat.io`) cannot authenticate this host. `system:image-puller` lets another namespace's ServiceAccount *use* a token; it does **not** attach credentials to the KServe ModelCar pull. The operator injects `spec.predictor.imagePullSecrets` from an OCI connection of type `kubernetes.io/dockerconfigjson`.

https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_on_projects/using-connections_projects#creating-an-oci-compatible-connection-type-using-the-connections-api_projects[Creating an OCI-compatible connection]

Setup already created **In-cluster registry** in `{presenter_project}`, `{ran_project}`, and `{core_project}`.

. OpenShift AI → project `{presenter_project}` → **Connections**.
. Confirm **In-cluster registry**: OCI host `image-registry.openshift-image-registry.svc:5000` (the port is required).
. On deploy, that connection autoselects. A single match looks locked. Leave it. Do **not** create a second connection named after Granite.

=== Attach the Docker config JSON (customer procedure)

Walk this once as the private-registry talking point. On stage, keep the setup connection — do not add a second host match.

The default ServiceAccount pull secret is type `kubernetes.io/dockercfg` (legacy `.dockercfg`, a host map). The dashboard and KServe need `.dockerconfigjson` with an `auths` wrapper. Uploading `.dockercfg` unchanged stores hosts at the JSON root; KServe reports `authentication required`.

From the OpenShift Web Terminal or a workstation with `oc` (do **not** cat the file on the projector):

----
NS=telco-ops-demo
SECRET=$(oc get sa default -n "$NS" -o jsonpath='{.imagePullSecrets[0].name}')
oc get secret "$SECRET" -n "$NS" -o json \
  | python3 -c 'import base64,json,sys; cfg=json.loads(base64.b64decode(json.load(sys.stdin)["data"][".dockercfg"])); json.dump({"auths": cfg}, sys.stdout)' \
  > /tmp/in-cluster-registry.json
----

Then in the dashboard:

. **Connections** → **Add connection** → **OCI-compliant registry**.
. Name: `In-cluster registry`.
. OCI storage location: `image-registry.openshift-image-registry.svc:5000` (include `:5000`; do not paste the registry ClusterIP).
. Access type: **Pull**.
. Upload `/tmp/in-cluster-registry.json` as the Docker config JSON. Not the raw `.dockercfg`.
. **Add connection**.

If a leftover Granite-named connection is already in the list, delete it after **In-cluster registry** exists. Matching is by OCI host, not by model name.

== 4. Deploy the registered version

. Version `workshop` → ⋮ → **Deploy**. Project `{presenter_project}`.
. Connection **In-cluster registry** autoselects. Leave it.
. Hardware profile: *NVIDIA L4 - 1 GPU*. Serving runtime: vLLM NVIDIA GPU.
. Advanced settings: **Model access**, **Require token authentication** (`workshop-infer`).
. Custom runtime arguments (no leading space): `--max-model-len=8192`
. Review → **Deploy**. Wait **Ready**.

If ImagePullBackOff still says `authentication required`, the connection's `.dockerconfigjson` has no `auths` map. Recreate **In-cluster registry** with the convert-and-upload steps, delete the failed InferenceService, deploy again.
